# Linux 手工测试矩阵

本文对应主工作树中的 `docs/LINUX_UX_OPTIMIZATION_PLAN.md` M0（第 7 节）
与 M2 必测组合（第 9.1 节）。M0 建立矩阵结构与状态追踪；
每个候选版本按此矩阵逐项人工验证并填入状态。

## 状态约定

- `✅ 通过`：在记录的环境下验证通过，且有证据（截图/日志/复现步骤）。
- `❌ 失败`：可复现失败，已按 issue 模板记录。
- `⛔ 阻塞`：当前环境无法执行（缺硬件/缺图形会话/工具不可用），并写明原因。
- `⬜ 未测`：尚未执行，不得填为通过。

每项必须携带：版本、桌面环境、显示协议、缩放、数据规模、提交 SHA、验证人、
日期。

## 环境信息（每次记录从应用内只读诊断获取）

`runtime_diagnostics` Tauri 命令与 `scripts/inspect-plan-scale.sh` 提供：

- MiriaGo 版本、Tauri 版本、WebKitGTK 版本。
- `XDG_SESSION_TYPE`、`XDG_CURRENT_DESKTOP`、`XDG_SESSION_DESKTOP`。
- 数据目录、日志目录、portal 后端提示。
- 数据规模（empty/medium/large）。

## 检查项（与 §9.2 对应）

- [ ] 窗口、任务栏、Alt+Tab、桌面菜单使用同一 application ID 和图标。
- [ ] 分数缩放下文本、图标、地图清晰。
- [ ] 鼠标点击位置、地图手势、拖放坐标无偏移。
- [ ] 窗口在不同缩放显示器间移动后正常。
- [ ] fcitx5 候选窗口位置、组合输入、回车确认、快捷键冲突正常。
- [ ] XDG Portal KDE/GTK 后端文件对话框能打开、取消并返回 Unicode 路径。
- [ ] `xdg-open` 正确调用 KDE KIO 与默认浏览器/地图应用。
- [ ] 深色主题下 Flutter、HTML、WebKitGTK 原生对话框、地图控件保持可读。

## 手工回归流程（每个候选版本）

来自计划第 15 节：

1. 从桌面菜单启动并确认任务栏图标关联。
2. 创建计划、作品、片区和点位。
3. 打开地图、切换点位并启动外部导航。
4. 导入含 Unicode 路径和图片的 `.sjhplan`。
5. 导出 `.sjhplan` 和 CSV，并取消一次保存对话框。
6. 打开记录详情和自动调色，确认资源可读写。
7. 重启应用，确认设置、当前计划和窗口状态恢复。
8. 断网启动并检查已缓存内容。
9. 在 KDE Wayland 分数缩放下移动窗口、输入中文并切换显示器。
10. 升级 pacman 包后确认用户数据未被覆盖。
